# Fashion shot list and production QC template

Use this when a developer/Planner must generate an **actionable deliverable**, not for a short general question. Every field is proposed until a person approves and the server saves the exact version.

## Input contract (identify missing values)

- Verified brand and target channel; exact products/SKUs/looks; creative brief and intended audience.
- Production date/time zone, location constraints, talent, crew, lighting/equipment, budget assumptions.
- Requested deliverable counts and crops (e.g. product PDP front/back/detail and campaign hero).

## Proposed shot record

| Field | Meaning |
| --- | --- |
| shot_ref | Stable draft reference; not a database ID unless saved |
| sku_or_look | Product/look included |
| composition | Front, back, detail, lifestyle, etc. |
| setup | Studio, beach, location, lighting and props |
| talent | Model/pose/usage requirements if known |
| channel_crop | PDP square, web banner, social portrait, etc. |
| priority | Must-have versus optional |
| estimated_minutes | Estimate, explicitly not booked time |
| acceptance_criteria | Observable image-quality and deliverable QC |
| status | Proposed / approved / captured / selected / rejected |

## Example — a six-outfit swimwear shoot

| Shot | Look | Composition | Setup | Deliverable |
| --- | --- | --- | --- | --- |
| S01 | Look A | Front | Studio softbox | PDP front |
| S02 | Look A | Back | Studio softbox | PDP back |
| S03 | Look A | Lifestyle | Beach natural light | Social hero |
| S04 | Look B | Fabric detail | Studio macro | PDP detail |

Repeat planned coverage for remaining outfits; do not invent precise total shot count, talent booking, vendor rates or actual captures without input.

## QC before claiming completion

- Every required SKU/angle/channel has approved planned coverage, clear owner, and visual acceptance criterion.
- Group setups to avoid unnecessary lighting/location changes; separately identify break, location and contingency time.
- Verify whether a *planned shot* actually resulted in a usable, approved *asset*. Missing captures become specific reshoot tasks.
- Compare deliverables to agreed scope, note unresolved assumptions, and retain exact approved version.
- Reject/cancel writes nothing; an authorized duplicate approval saves only once and reads back canonical results.
